# 生产兼容基线

## 目标

开源整理只能增加通用能力，不应迫使 Koobai 改变既有发布、同步和维护习惯。

用户可感知流程默认保持：

> 打开写作页面 → 输入内容 → 上传图片 → 提交到 GitHub → 自动处理与构建 → Cloudflare Pages 更新。

## 必须保持的入口

- `/newlaodao`
- `/newsuibi`
- `/movies`
- `/exercise`
- `/zouguo/`
- `/posts/`
- `/laodao/`

现有文章和唠叨永久链接不可因开源整理发生批量变化。

## 必须保持的内容契约

- `content/posts/`
- `content/laodao/YYYY/MM/`
- `content/zouguo/`
- `content/pages/`
- 现有 Front Matter 字段与日期格式。
- 唠叨文件名的时间规则。
- 文章 Slug 行为。
- 评论与点赞以页面路径作为标识的行为。
- 中文保留 Tag“走过”、`zouguo.occurred_at`/`zouguo.place`、三类来源身份和经纬度顺序。
- `/zouguo/index.json` 与边界子集继续由 Hugo 生成，不改为手工数据源。

后续 Schema 默认用于校验和提示，不用于强制重写全部历史内容。

## 必须保持的浏览器状态

重构编辑器或互动脚本时，需要兼容当前 LocalStorage 数据：

- 管理员发布 Token。
- 随笔本地草稿。
- 唠叨本地草稿。
- 评论用户资料。
- 评论管理员状态。
- 点赞状态。
- 主题偏好。

如确实需要更名，必须实现读取旧值、写入新值并保留回滚期的自动迁移。

## 必须保持的自动化契约

- `main` 分支推送继续触发生产构建。
- 原始运动数据提交继续先经过处理工作流。
- 月报自动提交不得造成工作流自循环。
- `Auto-sync activity facts` 等原始事实提交标记继续用于历史识别和排障；实际触发边界由文件路径保证。
- `Auto-generate monthly coaching report` 等提交信息判断继续有效。
- 现有 GitHub Secrets 在明确迁移前继续生效。
- Cloudflare Pages 生产项目和域名不在文档阶段改变。

## 必须保持的动态接口

除非项目所有者批准带回滚方案的接口迁移，否则保留：

- API 路径。
- HTTP 方法。
- 管理员 Header 名称。
- Turnstile Header。
- 请求与响应字段。
- GitHub 内容写回行为。
- 图片路径规则。
- 云草稿兼容字段。

## 高风险阶段的切换规则

### 前端模块重构

- 一次只抽取一个公共能力。
- 新旧实现对比 Front Matter 和请求 payload。
- 不同时改变 UI、数据格式和接口。
- 生产入口在验证通过前继续使用旧实现。

### Worker 开源

- 先导入源码并补测试。
- 使用测试域名、测试数据库和测试仓库。
- 与生产接口进行合约对比。
- 未通过发布、上传、草稿、评论和点赞回归前不切换生产。

## 回归检查表

### 基础站点

- 严格 Hugo 构建成功。
- 首页、文章、唠叨、标签、RSS 和 JSON 可生成。
- 既有永久链接未改变。
- 站内链接没有新增失效项。

### 网页写作

- 登录与退出。
- 新建和修改随笔。
- 新建和修改唠叨。
- 单图、多图和粘贴上传。
- 本地草稿和云草稿。
- Markdown 预览与标签补全。
- GitHub 文件路径、内容和提交信息正确。

### 自动数据

- 豆瓣增量同步。
- 原生 App 通过 Activity Sync Gateway 写入来源无关的运动事实。
- 运动隐私处理。
- 月中与月末报告状态机。
- 处理后自动提交与生产部署。

### 动态服务

- 评论读取、提交、回复和删除。
- 点赞与重复点赞保护。
- Turnstile 成功和失败路径。
- 图片上传与云草稿增删改查。
- 独立走过发布/编辑/删除，唠叨和随笔移出走过时不误删原内容。

### 走过页面

- 独立走过、唠叨和随笔三类来源均能聚合且不重复。
- 当前年与历史年份日期格式正确，来源标记和文章跳转正确。
- 新增省份、城市或海外国家后只生成实际引用的边界子集，浏览器不下载完整目录。
- 纯文字、单图、双图和多图列表/灯箱正常；移动端列表不依赖地图联动。

## 变更验收原则

每个影响 Production 的改动必须先完成相应回归。通用功能可以延期或关闭，但不能让 Koobai 生产站点处于半迁移状态。
